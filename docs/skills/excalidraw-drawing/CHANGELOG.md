# excalidraw-drawing changelog

## 3.3.0 (2026-11-17)

- New page option `"titleFont": "iowan-inked"`: the title in Iowan Old Style Bold with a slightly inked edge, drawn only in the PNG. From a benchmark chart whose hand-drawn title read too casual for the post; after side-by-side tries of serif, slab and mono titles, plain and roughened, the owner chose this one. Excalidraw can't use another font, so the `.excalidraw` file keeps the title in Excalifont and names the font in its `customData`; `drawing.mjs render` draws it too, so a preview after a hand edit keeps it. The edge is an SVG filter (two sizes of noise displacing the outline, then a blur and a sharpened alpha) rendered by the runtime's resvg, so no new dependency. The font comes with macOS and isn't copied into the skill; without it the build warns and draws Excalifont. An unknown `titleFont` stops the build.

## 3.2.0 (2026-11-14)

Slide decks for talks. From building a 20-minute talk of about 35 slides with the skill, where everything beyond a single `16:9` slide had to be made by hand around it: planning the story, writing slides people can follow, revealing parts click by click, and the files a speaker needs.

- New `references/slides.md`, loaded only for a deck: plan the talk before drawing (about a minute per content slide, at 120 to 150 spoken words a minute, sections with a map slide, one point per slide with a title that says it), keep slides picture-first with the evidence in a small footer and the argument in the speaker notes, one visual language for the whole deck, type a room can read, real and familiar examples, numbers drawn rather than listed (a part of a number recoloured inside one grid, a separate experiment set apart), redrawn charts labelled as approximate with only the source's own figures exact, every figure checked against its primary source, and a whole-deck review of flow, words, facts and timing before calling it ready.
- Elements take `step` (1 to 12): the click a part of a slide appears on, with the footer on the last, a bound label with its shape, and a joined arrow with the later of its shapes; a gap in the steps is a warning. `build.mjs --steps` writes `<name>.step-1.png`... one picture per click before the last, with later parts hidden rather than removed, so nothing moves between clicks. Step pictures carry a marker and are written together with the drawing and its PNG; a build removes the ones it wrote before and doesn't have now, so a deck never shows a stale one, and never replaces or removes a file at those names that it didn't write. The guidance: a click only where revealing something makes a point, since a first deck with reveals on 26 of its slides was too many.
- New `scripts/deck.mjs`: builds every slide spec in a folder (in file-name order, notes from each spec's `notes` or the folder's `notes.json`) and writes `index.html` (a browser deck with notes, an overview, full screen and the steps, which B turns off), a PDF of the finished slides, and a PowerPoint whose steps fade in on clicks with the notes in the presenter view, a slide that isn't 16:9 kept in its own shape. The three are written together, and never over a file of those names it didn't write. Review (Deep): the browser deck's slide grid couldn't be hidden, since its own display rule beat `[hidden]`; outputs and step pictures could replace or delete files the scripts didn't write; and a failed render could leave old and new step pictures mixed. Round 2: the three deck files are now put back as a set if any fails to move in, the deck uses only step pictures a build marked for that slide, an arrow joined to a figure or stack, or named by from and to, waits for it, and a slide's build refusing explains that `deck.mjs --force` covers only the deck's own files. Round 3: a step picture's marker names its slide and its build, so pictures from two builds, or another slide's, are left out of the deck; the earlier deck files are removed only once the new set is in place; a folder at an output's name is refused, not a crash. Round 4: that folder could still be moved aside and deleted with `--force`; now nothing but a file is ever replaced, and nothing is removed recursively. A step picture's marker is read whole, so a long non-ASCII slide name keeps its pictures, and the deck takes only pictures with a build id and this slide's name. All fixed, with tests.
- The runtime pins `pptxgenjs` 3.12.0, `pdf-lib` 1.17.1 and `jszip` 3.10.1 for the PDF and PowerPoint.

## 3.1.0 (2026-11-13)

- New `16:9` format (1500×844) for slides: one spec per slide, a full-width panel without a frame, and larger type than on a page, since a slide is read from across a room. From turning a one-page infographic into a 20-minute teaching deck: every page format was portrait or square, so a slide would have left a band of empty space on a wide screen. The test builds a slide and checks that an overfull one warns.

## 3.0.0 (2026-11-07)

Major because the build now writes different files inside an Obsidian vault, and refuses to replace a hand-edited drawing it used to overwrite. From a first page built into an Obsidian vault with the Excalidraw plugin 2.29.2 and then edited there by its owner and by an agent in turns: the page opened in compatibility mode until converted by hand, a heading broke onto a second line over a caption, the build's PNG and the plugin's auto-exported PNG went out of step, and the agent's follow-up edit needed a one-off script and renderer.

- Wrapped text keeps a little room. Excalidraw shrinks a wrapped text to its widest line; the plugin measured a 24 px heading 0.5 px wider than this renderer and wrapped it again. Headings, takeaways and every `text` with a `width` are now saved 2% and 2 px wider than their widest line, never wider than the width they were wrapped to. The same shrink drew a centred text with a `width` (and a top label, which is centred) from the left edge of its box; it is now centred in it.
- Inside an Obsidian vault (a `.obsidian` folder in or above the output folder) the build writes the plugin's own `<title>.excalidraw.md`, with uncompressed JSON and the Text Elements list the plugin reads words from, and `<title>.excalidraw.png`, the name the plugin's auto-export keeps current. The plugin matches each listed text by an 8-character id, so texts get one, the same on every build. `--name`, `--obsidian` and `--no-obsidian` override the name and the detection; the skill keeps `page.json` outside the vault and builds with `--out-dir`.
- The build stops with exit 1 instead of replacing a drawing that an editor (Excalidraw, excalidraw.com, the Obsidian plugin) has saved since it was built, which it tells by the file's `source`; `--force` replaces it. Before, the skill only warned that building again overwrites hand edits.
- New step 5 and `references/editing.md`: change an existing drawing in place, never by rebuilding it. In Obsidian the user closes the drawing's tab first, since an open drawing's next save overwrites the file. New `scripts/drawing.mjs` reads and writes a `.excalidraw` or `.excalidraw.md` with its formatting kept byte for byte, gives changed elements new versions, keeps a text's `originalText`, `rawText` and the Text Elements list in step with its `text`, and renders a preview (`node scripts/drawing.mjs render <drawing> <out.png>`, the size of the plugin's 1x export). A compressed drawing is refused with the setting that turns compression off.
- Unknown arguments to the build are now a usage error (exit 2) instead of being ignored, so a mistyped `--no-obsidian` can't silently write the wrong files.

## 2.0.0 (2026-11-06)

- Renamed from `sketch-infographic` to `excalidraw-drawing`: since 1.1.0 it draws charts and diagrams as well as infographic pages, and the old name described only the pages. The new one names what every picture is made in, so it stays true as more kinds are added. A host or prompt that calls `sketch-infographic` must use the new name; the skill, its docs, its test (`tests/excalidraw-drawing-test`) and its install links all moved, and the runtime override is now `EXCALIDRAW_DRAWING_RUNTIME`. Releases up to 1.1.0 are tagged `sketch-infographic/v<version>`; from 2.0.0, `excalidraw-drawing/v<version>`. On a computer that installed the old name, bootstrap removes the old links (`retired` rows in `install/links.tsv`, a new mode: a link is removed only while it points at this checkout's old folder; a link to a `skills/sketch-infographic` folder elsewhere, from another or a moved checkout, is kept and reported for the owner to remove, and anything else at the path is kept), uninstall removes them too, and doctor fails while one of this checkout's is left and warns about one from another checkout. From the review (Deep, five rounds; Codex GPT-6.1 Terra, Claude Sonnet 5.5, DeepSeek V4.1 Flash free, GPT-6 Luna on trial): the first version of the rename left the old links dangling on every other computer; removing any broken link of the right shape could delete one this repository never installed. The `.excalidraw` files it writes now give `excalidraw-drawing` as their source; nothing else about what the skill draws changed.

## 1.1.0 (2026-11-06)

- Draws single diagrams as well as infographic pages: the description and the workflow now cover a line or bar chart, flowchart, boundary, sequence diagram, timeline, quadrant, cycle, tree or comparison table, planned from the user's numbers, description or example image. From redoing three kinds of example image as a test (a line chart, a flow diagram and a sequence diagram): all three built, but only by tracing points by eye, passing an undocumented Excalidraw field through, and fighting the page frame, and a request for "a hand-drawn chart" might not have loaded the skill at all.
- New `references/diagrams.md`: a table for picking a diagram by its point, then one tested full-width snippet per kind with what to watch for. The test builds every one, so a snippet can't silently break.
- New `chart` element: a line chart (series of points, axes with optional ticks, grid and markers, each series named at its first or last point) or a bar chart, scaled from the numbers, so no point or bar length is worked out by hand. A point or tick outside its axis, a squeezed plot, a series of fewer than two points or a negative bar is a warning. The patterns' bar chart uses it instead of hand-scaled rectangles.
- `"curve": true` on a line or arrow draws a smooth curve through its points; `"frame": false` on the page or a panel drops the panel's card and padding; `"format": "fit"` also trims the page's width to the drawing. Arrow labels are documented as drawn over by their line in the PNG, with a text beside the arrow as the alternative, after the first flowchart in the catalog had "yes" and "no" struck through.
- Reviewed at Standard (Codex GPT-6.1 Terra; Claude Haiku 5.5 on trial). Fixed from it, each with a test: an all-zero line series was dropped, a start label sat by the axis even when its series started further right, a zero bar looked like a small one, charts with y ticks drew curves that could bulge past their measurements (now straight by default), series names pushed apart could leave the chart's box, and the catalog test skipped a diagram whose snippet was missing.
- A gallery of every catalog diagram, rendered, in `docs/skills/sketch-infographic/gallery/` (since 2.0.0, `docs/skills/excalidraw-drawing/gallery/`), for the owner to pick from; agents never load it.

## 1.0.0 (2026-11-05)

- First release: plan a page from one source (title, five to seven panels, footer), write it as a JSON spec, and build it into a PNG and an editable `.excalidraw` file. The build lays out a two-column grid, wraps text, routes arrows, and warns about elements outside their panel, overlaps, boxes that grew for their label, and characters Excalifont lacks. From recreating a hand-drawn infographic seen on X as a private test: the first build showed that typed arrows and check marks fall back to a system font, that the renderer centres a label it was asked to put at the top, and that an overlap check skipping text inside boxes misses the collision that results.
- Pages have a fixed shape, 3:4 portrait (1500×2000) by default, with 4:5, A4, square and auto. The plan fills the page with six or seven panels, keeps every panel of an example page, and the check compares against it side by side. Type sizes, margins and panel padding are measured from two 1500×2000 example pages. From the owner's review of the first test page: it came out 1500×1670 against the example's 1500×2000, with a row of panels missing and larger type.
- Takeaways sit right under the drawing instead of at the panel's bottom, so a stretched panel keeps its words with its picture; left-aligned box labels, hex stroke colors, sheets without "•••" and stacks fanning up and to the right work; empty text is skipped instead of crashing Excalidraw's restore.
- A `group` field keeps a drawing's parts together, and the build warns when an arrow or line runs through text. From recreating a second example page: an arrow crossed a caption without a warning, and a cylinder built from two shapes was reported as an overlap. That page first came out 207 px too tall for 3:4; the overflow warning's number was enough to tighten it to fit in two rounds.
- Arrows sharing a side of a box fan out along it, arrows to an ellipse end on its curve, and an arrow under 20 px is a warning; the visual check asks whether every arrow starts and ends on something. From the owner's review of the second recreation: three arrowheads stacked on one point of a circle, a dashed line started in empty space, and two pairs of boxes left arrows of 8 to 12 px.
- Reviewed at Deep before release, over three rounds (Codex GPT-6.1 Terra and Claude Sonnet 5.5; GPT-6 Luna on trial; both free reviewers ran out of time). Nine must-fixes, each fixed with a test: labels overflowing their box without a warning, text over text, a crash on a stack without an id or a panel without a heading or title, a PNG and an .excalidraw file left from different builds after a failed render or write, a flag without a value ignored, words too long for their text, and doctor checking the runtime for hosts that don't install the skill. The last two came in round 3, as many as round 2, so the gate stopped; the owner chose to fix them and merge without a fourth round.
- Draws with mcp-excalidraw-server 2.1.2's offline renderer (Excalidraw's own exporter under jsdom), pinned in `runtime/excalidraw` and installed with `--ignore-scripts`. Chosen over the official Excalidraw MCP server, which shows diagrams inside a chat but doesn't document saving files, and over drawing with rough.js in HTML, which only imitates the look and can't be edited in Excalidraw. Reviewed before pinning: the package itself has no install scripts (its only dependency with one is fsevents, an optional macOS watcher the renderer doesn't use), and it reaches the network only for its `share` command (json.excalidraw.com), which the skill never calls.
