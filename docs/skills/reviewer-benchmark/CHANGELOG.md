# reviewer-benchmark changelog

## 1.0.1 (2026-11-15)

- **A Claude reviewer's brief gives the diff as a command its allow list permits.** The brief said `git -C <copy> diff`, which the `Bash(git diff:*)` rule refuses, so the Claude models of the first two runs had their first command refused and went on with plain `git diff` (shown with one command each way, 2026-11-15; found by Claude Sonnet 5.5 reviewing review-gate 6.0.0). Now it says `git diff <base>...<head>`, run from the copy's folder, as it does for `agy`. Their saved reports stand: a later run of those models is that little bit easier for them.
- **A Claude reviewer reads no settings file.** With `--setting-sources local`, a `.claude/settings.local.json` in the copy that allows a tool gave the reviewer that tool whatever its list said: one that allows writing let a reviewer write a file (shown by a run, 2026-11-15; found by Codex GPT-6.1 Terra). The source list is now empty, and the reviewer starts in safe mode, without the owner's plugins, hooks and MCP servers (found by Terra, suspected; a run showed safe mode keeps the sign-in and the allowed tools).
- **A Claude reviewer can't write through `git diff --output=<file>`.** The allowed `git diff`, `git log` and `git show` take that option, and a run wrote a file with it. It is denied now, and a run shows the three commands still read.
- The built-in cheap models' brief is "the gate's brief for a free reviewer": review-gate 6.0.0 ended the trial that the wording named.

## 1.0.0 (2026-11-15)

- **A benchmark for reviewer models** (owner, 2026-11-15: "a rerunnable, versioned benchmark for these reviews", "stored properly"). Models review the owner's private set of past changes, whose defects are known, and their reports are scored blind. It replaces waiting for about 20 live trial reviews of each model, on different changes, with one evening on the same ones ([evidence.md](evidence.md)).
- **`scripts/bench`:** `setup` makes a copy of each change that holds nothing made after its review; `run` has one model review every change, read-only, with the review gate's brief, and records a review that passes its time; `blind` names the reports by letter for the scorers and `unblind` saves their scores under the models' names; `totals` prints one line per model.
- **Two scoring passes:** each report against the key, then every other blocker or follow-up against the code, with a verdict of real, true but minor, there before, or false. The second pass goes to the strongest model at hand.
- **The key grows:** a finding outside the key that held up is added to it, checked against today's code, and the set's version goes up, so the key doesn't stay tilted toward the reviewers who wrote it.
- **The data is the owner's:** the set, keys, reports and scores live in the private state repository, and the commits a key names are kept from deletion by a name in their own repository. Nothing of them is in this repository.
- `tests/reviewer-benchmark-test` checks the script with a made-up set, and the four reviewer tools' commands with stand-ins.
- **Review (Deep, by review-gate 5.0.0), 5 rounds, blockers 2, 0, 0, 0, 0.** Codex GPT-6.1 Terra found both blockers in round 1, fixed: after a key's commits changed, old reviews and their scores were reused for the new code, and a finding added to the key was counted twice. Keeping a score with its own review took three more rounds of Terra's follow-ups (an old blind copy, two reviews alike in size and time, a race with a run), settled by an id each review gets and its score carries; its round 5 found nothing. Claude Sonnet 5.5 found the gaps around a run: a failed review was never run again, stopping `bench` or closing its terminal left the reviewer running, `blind` could throw away or replace saved scores, and the tests didn't exercise the tools' commands; all fixed. Gemini 4 Hydrogen (trial) found the unpacking could hang and Codex's last-message file could be stale; DeepSeek V4.1 Flash (free) that a missing report crashed `blind` and that reviewers could find other reports beside their copy; all fixed.
- **Open, with no round left to review a fix:** `blind` doesn't say how many reports it left out as already scored (Sonnet, round 5). Models side by side share a change's copy, and a file marked `export-ignore` isn't in it; both are written down as limits.
